# Cartogate 0.8.0 — answers that fit in the agent's context

**Tool answers now have a size budget, and `repo_map` works on a repository of any size.**

Before this release, a tool returned every row it found. On Cartogate's own repository (421
files), `find_references` on the most-referenced function returned 48,071 characters, and
`repo_map` returned 199,316. Claude Code saves any tool result over 50,000 characters to a file
instead of showing it to the model. 0.8.0 caps each answer, says how to get the rest, and slims
the tool listing.

---

## Tool answers have a size budget

A list-returning tool called with no `limit` returns at most 20 rows within 8,000 characters
(about 2,000 tokens). `limit` can be raised to 200, and no list result exceeds 40,000
characters. The one exception is a single row larger than the ceiling, which is returned
whole rather than hidden.

On the same repository, the same calls now return:

- `find_references` on the most-referenced function: 4,564 characters (20 of 122 rows), down
  from 48,071.
- `blast_radius` at depth 3: 5,073 characters (20 of 209 rows), down from 59,327.

`count` is always the true total of matches, never the number returned. A cut result carries
`returned`, `truncated: true` and `next_offset`. Call again with `offset` set to `next_offset`
to continue. For `find_references`, `blast_radius`, `implementations`, `suggest_tests` and
`doc_drift`, a cut result also lists the files the matches are in (`units`, up to 40 paths)
and how many files there are in total (`unit_count`).

Tools that take `limit` and `offset`: `find_references`, `blast_radius`, `implementations`,
`suggest_tests`, `doc_drift`, `find_dead_code`, `find_duplicate_bodies`, `localize` and
`repo_map`. `impact_summary` takes `limit` only; its `counts` field keeps the totals.

Reference rows are smaller. Each row gives the file path once, in `location`, and the `unit`
field is gone. Call sites are line numbers in `lines` instead of `path:line` strings in
`sites`. A call site in a different file than its row keeps the `path:line` form under
`sites`. `signature` appears only on rows that share a name (overloads).

A test row's `exercises` and a doc row's `mentions` list at most five names; the rest are
counted in `more_exercises` and `more_mentions`.

Only the MCP answers changed. Cartogate's own gates (the write-time hook and the pre-commit
gate) still read complete results.

## repo_map works on a repository of any size

On the same repository, `repo_map` with no argument now returns 571 characters, down from
199,316.

It lists files while they fit in one page, and directories when they do not, as deep as still
fits. Each directory row has the number of files and symbols under it. Overview rows give
export names only; signatures are in the per-file view.

- `module=<directory>` zooms into a directory. A row named `x/.` means the files directly in
  `x`. Any row's name can be passed back as `module`.
- `module=<file>` gives that file's exports with signatures, and the files that import it
  (`dependents`, with `dependent_count`). `dependents_truncated` is set when the list was cut.

## A smaller tool listing

The part of the tool listing every client sends to the model (tool name, description and input
schema) is 11,047 bytes for `cartogate-mcp`, down from 12,917 in 0.7.1, even though ten tools
gained paging arguments. The `workspace_root` parameter is described in one line; the full
explanation appears once, in the server instructions.

The whole `tools/list` payload is larger than in 0.7.1: 30,475 bytes against 13,745, because
every tool now advertises an output schema, a title and annotations (see below). It was 41,130
before this release's slimming.

## MCP SDK 2.x

Cartogate now requires the MCP Python SDK 2.x (`mcp>=2,<3`). 0.7.1 used 1.x. Installing 0.8.0
brings the right SDK version with it.

Every tool now has a display title, behavioural annotations (read-only or not) and an
advertised output schema. Each result is sent both as JSON text and as structured content, so
text-only and schema-aware clients see the same answer.

## Fixes

- `check_duplicate` called without `language` used to search only the Python table, so a
  duplicate in another language came back as a silent all-clear. It still checks as Python by
  default. A match in any other language now comes back as `near_match`, with a `note` naming
  the languages that matched. That does not block: pass `language` to get a blocking answer for
  the language you are writing.
- `repo_map` given a directory path used to return "not found". It now returns that
  directory's overview.

## Upgrading

Cartogate installs from git: a release is a tag plus a `stable` fast-forward.

```bash
pipx install --force "git+https://github.com/cartogate/cartogate.git@stable"
cartogate --version          # 0.8.0
```

If `pipx` reports the venv is locked, run `cartogate daemon stop --all` first. Restart the
editor so it picks up the new server. A warm daemon from an older version is
replaced automatically.

Anything that parses tool results from 0.7.x needs a change. `find_references`, `blast_radius`
and `implementations` rows no longer have `unit`. `find_references` rows have `lines` instead
of `sites`. `repo_map` overview rows give `exports` as names, not objects, and a large
repository comes back as `dirs` instead of `units`. Lists may be cut, so read `count` for the
total and follow `next_offset`.

Agents need nothing to change. A truncated result says so and says how to continue.
