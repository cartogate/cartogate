# Cartogate 0.7.1 — the gates actually fire

**A point release that makes 0.7.0 real.** 0.7.0 shipped verification contracts, a tamper-evident
audit ledger, and Devin agent support — but on the Devin Desktop surface two of the gates could not
enforce anything, and the contracts and ledger were invisible to the agent. In practice, 0.7.0
looked a lot like 0.6.0 from inside an agent session. This release fixes both halves.

Everything still runs entirely on your machine. No cloud, no network calls, no language model of
its own. Every answer traces back to a line of source or a recorded fact.

---

## The Devin Desktop gates actually fire

An **inert gate is the worst failure mode there is**: it looks installed, reports itself as
installed, and enforces nothing. 0.7.0 wired hooks into both Devin Desktop agents, but two of them
could not act on what they received.

- **The write gate reads the real payload shape.** Cascade nests proposed code in
  `tool_info.edits[].new_string`, while `normalize()` read only the `tool_info` root — so the
  pre-write gate extracted nothing and passed every write. It now walks the edits array, taking the
  first code-bearing key per edit and skipping malformed entries.
- **Matching decides from the payload, not the tool name.** Devin's built-in edit tool names are
  unpublished, and a name matcher that guesses wrong is inert. The matcher is deliberately
  catch-all; the gate judges the payload instead. Blast radius is pinned in both directions by
  test — prose in a risk key passes, duplicate-shaped code blocks.
- **Cold start: 405ms → 92ms.** A catch-all matcher spawns the gate on *every* tool call, so
  cold-start cost became the whole agent loop's cost — and roughly 290ms of it was a single import.
  The payload key list moved into a leaf module with no internal imports, the write gate's own
  imports became lazy, and it now short-circuits before touching the extractor. Pinned by test.
- **`stopgate --advisory` — report, never refuse.** Cascade's session-end event fires every turn
  and cannot block, so a blocking stop gate would nag on every turn and never actually bind.
  Advisory mode exits 0, spends no refusal budget, writes no ledger entry, and stays silent unless
  a locked contract is unsatisfied.
- **The integration docs were wrong and are now correct.** The claim that this surface exposes no
  third-party pre-write hooks was false. It is replaced with the verified matrix: two agents in one
  namespace, both hook dialects, the catch-all rationale, the edits-array shape, advisory stop, and
  dual MCP config paths. See [`docs/INTEGRATIONS.md`](../INTEGRATIONS.md).

## Contracts and the ledger, exposed to the agent

0.7.0 shipped both features but gave the agent no way to *see* either one, and the always-on rule
still taught only the 0.6 tools. Two new read-only MCP tools close that gap. Both degrade to a
`note` rather than raising, and import the contract and ledger modules lazily so the cold-start win
above is not clawed back.

- **`contract_status`** — the active contract, whether it is LOCKED, per-check pass/fail (failing
  checks carry their output tail), and pending attestations by name. Without it, an agent's first
  encounter with a locked contract is being refused at session end, with no way to read the
  definition of done. See [`docs/CONTRACTS.md`](../CONTRACTS.md).
- **`gate_history`** — recent ledger decisions, newest first, clamped to 50 rows with an honest
  `total`. After a BLOCK, an agent can see that it is about to repeat a move that was already
  refused. See [`docs/AUDIT.md`](../AUDIT.md).

The always-on rule now teaches both, plus the part that actually matters: with a locked contract,
*done* is not the agent's to declare. Make the checks pass; do not edit the contract to fit the
work; do not reach for `--no-verify`; and when a human attestation is pending, say so and stop
rather than claiming completion.

Tool surface stays deliberately small — some agent surfaces cap at 100 tools, and every marginal
tool degrades selection accuracy. Several candidates were considered and left out on purpose.

## Fixes

- **A malformed argument could tear down the daemon** (Critical, caught in review rather than by
  the tests). Tool dispatch coerced numeric arguments *before* each tool's own fail-open guards, so
  a JSON `null` raised `TypeError` past every defense. Reproduced live over TCP against a real
  daemon, where it escaped the response handler and took down the whole task group.
- **CI is green again.** 0.7.0 was published from a red internal main and shipped a lint violation
  as a result. This release also de-flakes the popup discovery-guard end-to-end test: the popup's
  POST is script-initiated, so it is not a subresource and does not hold back `load` — the
  assertion could race the abort on a contended runner. It now polls to a deadline, pumped with
  `page.wait_for_timeout` (Playwright's sync API only dispatches route handlers while the main
  thread is inside a Playwright call, so sleeping would spin without ever letting the handler run).

## Upgrading

Cartogate installs from git — a release is a tag plus a `stable` fast-forward, nothing to download.

```bash
pipx install --force "git+https://github.com/cartogate/cartogate.git@stable"
cartogate --version          # 0.7.1
```

No migration and no configuration changes. If you already ran `cartogate init` for a Devin Desktop
agent under 0.7.0, re-run it to pick up the corrected hook wiring:

```bash
cartogate init --agent devin
cartogate hooks status       # confirm what is actually installed and firing
```
